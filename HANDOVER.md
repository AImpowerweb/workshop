# Handover — AImpower.org research prototype site

Everything a new maintainer needs to run, change, and publish this site.

> `README.md` is a different document: it is the *design specification* for the
> 12 prototypes, written for someone rebuilding them in another codebase. This
> file is about operating **this** website.

---

## 1. What this is

A bilingual (English default, 中文 toggle) showcase for **12 hand-coded,
interactive prototypes** about speech accessibility for people who stutter.
Visitors browse cards on the landing page and open a dedicated page per
prototype where the interface actually runs — nothing is a video or a mockup.

**Stack:** React 18 + Vite 5 + Tailwind CSS. Plain JSX, no TypeScript.
No backend, no database, no API keys. It is a fully static site.

---

## 2. First 15 minutes

You need [Node.js](https://nodejs.org) 18 or newer (built on v25, npm 11).

```bash
cd "AIMpower website"
npm install
npm run dev
```

Open <http://localhost:5173>. Edits to files under `src/` appear instantly.

| Command | What it does |
| --- | --- |
| `npm run dev` | Live development server. What you use while working. |
| `npm run build` | Compiles everything into `dist/` — the publishable site. |
| `npm run preview` | Serves the built `dist/` locally, to check before deploying. |

Run `npm run build` before handing anything on: it fails loudly on a broken
import or bad JSX, so it doubles as a correctness check.

## 3. Version control

The site lives at **<https://github.com/aimpowered/workshop-prototypes>**
(remote `origin`). Clone it rather than copying the folder:

```bash
git clone https://github.com/aimpowered/workshop-prototypes.git
cd workshop-prototypes
npm install
npm run dev
```

`node_modules/` and `dist/` are regenerated by the commands above and are both
gitignored, so neither is in the repository.

⚠️ **Never restore this project by dragging a folder over `src/`.** Early in
development exactly that replaced every component, and recovery was only
possible by replaying the edit history. Exports from design tools are *partial*
bundles — merge them file by file and diff before accepting anything.

## 5. The two things to understand before editing

### Everything bilingual goes through `t()`

Copy is never a bare string. It is an object with both languages, rendered
through `t()`:

```jsx
import { useLanguage } from '../context/LanguageContext';

const { t } = useLanguage();
<p>{t({ en: 'On call', zh: '通话中' })}</p>
```

Site-wide copy lives in `src/data/content.js`; per-prototype copy in
`src/data/prototypes.js`; copy inside a prototype's own UI is inline in that
prototype's file. **If you add text and skip `t()`, it will not translate.**

### Prototypes are desktop-sized and get scaled

Most prototypes are built on a fixed 1024px canvas. `ScaledPrototype` measures
the available width and CSS-scales them down to fit, so they stay fully
interactive at any window size. Two are device-sized instead (a phone at 462px,
a watch at 440px) and declare that via `canvas: { w, h }` in `prototypes.js`.

Consequence: on a phone a 1024px prototype scales to ~0.32, which renders 16px
text at about 5px. That is why the mobile handling below exists.

## 6. Common tasks

### Change wording on the site
`src/data/content.js` — hero, section headings, buttons, the workshop and team
pages. Every entry has `en` and `zh`; update both.

### Change a prototype's title, description, or tags
`src/data/prototypes.js`. Tags come from `TAG_LABELS` in the same file; the
counts beside each filter update automatically.

### Change what a prototype does
Edit its file in `src/components/prototypes/`. They are self-contained — icons
are inline SVG, styles are Tailwind classes. Arbitrary values like
`text-[13px]` are deliberate: they are the design, so don't round them to a
scale.

### Add a new prototype
1. Add the component to `src/components/prototypes/`.
2. Register it in `registry.js` (`'my-id': MyComponent`).
3. Add an entry to `src/data/prototypes.js` with `page: true`, `tags`, and
   `canvas` if it isn't 1024px wide.
4. Capture a thumbnail in both languages (§7).

### Hide a prototype from the grid
Set `hidden: true` on its entry. It stays reachable at its own URL. Used for
自定义情绪标记, which appears inside the Emotion Journal page instead of as its
own card.

### Regenerate card thumbnails
See `tools/thumbnails/README.md`. It documents three headless-Chrome traps that
each silently produced screenshots with content missing — read it before
changing the capture.

## 7. Mobile behaviour

Deliberate, and worth knowing before you "fix" it:

- The **page layout is fully responsive** — no horizontal scrolling, cards
  stack, text reflows.
- On phones a desktop-sized prototype is **not usable inline** (~5px text), so:
  tapping it opens a **fullscreen view**, its input is suppressed inline so taps
  can't hit invisible controls, and a quiet caption under the frame explains why.
  In landscape fullscreen the scale reaches ~0.78, which is legible.
- Device-sized prototypes (phone, watch) skip all of this — they already fit.
- Touch targets are ≥44px on phones, reverting to compact sizing from `sm:` up.

The phone breakpoint is `(max-width: 767px), (max-height: 600px)` in
`src/hooks/useMediaQuery.js` — the height clause matters, because a rotated
phone is 812px wide and a width-only test would treat it as a desktop.

## 8. Publishing

The site is live at **<https://aimpowered.github.io/workshop-prototypes/>**.

**Deploys are automatic.** Every push to `main` runs
`.github/workflows/deploy.yml`, which does `npm ci && npm run build` and
publishes `dist/` to GitHub Pages. It takes about a minute; watch it under the
repository's **Actions** tab. There is no deploy command to run and no hosting
account to manage — pushing *is* deploying.

GitHub Pages allows only one deployment at a time, so the workflow sets
`cancel-in-progress: true`. Push twice in quick succession and the older run is
superseded rather than the newer one failing.

**To host it somewhere else,** `npm run build` still produces a plain static
`dist/` that any host will serve (Netlify, Vercel, S3, Cloudflare Pages). One
detail matters if you do: `vite.config.js` sets `base: './'` so the build works
from a subfolder — that is what makes the `/workshop-prototypes/` path resolve.

## 10. Gotchas that cost real time

- **Prototypes came from a design tool as partial bundles.** They must be
  *merged* file by file, never by replacing the `src/` folder — that is what
  destroyed the app shell once. Diff before accepting any bulk import.
- **The dev server is not the website.** If a preview link stops working, the
  server has stopped; restart with `npm run dev`. It is not a code problem.
- **Verify visually, not just by reading the code.** Several bugs — invisible
  banners, an empty chat pane, text hidden under the phone's Dynamic Island —
  looked perfectly correct in the DOM and were only visible in a screenshot.
- **Two prototypes share the 小美 avatar** via `MeiAvatar.jsx`. They previously
  had separate copies that drifted apart (one had pink hair, the other dark).
  Keep it shared.
